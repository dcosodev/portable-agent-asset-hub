# S2 contract and gate

Core has no SQLite imports. The frozen public API exports opaque identity types/prefix validation, policy/actor context, errors, audit, storage contracts, and idempotency types. IDs are `usr_`, `agt_`, `hrn_`, `bnd_`; Agent creation requires an existing User, Harness has no owner, and scope is `{ownerUserId, agentId}`. Out-of-scope reads are indistinguishable from 404. Admin capabilities deny by default. Actor context is server-created and frozen.

The public storage API exports only governed `SqliteStore`, path-based `backupDatabase`, `HubError`, and non-sensitive diagnostics types. `HubDatabase`, raw `DatabaseSync`, `doctor(db)`, `migrate(db)`, and `loadMigrations` are internal details and are absent from package entrypoint/subpath exports. `SqliteStore.transaction(actorContext, callback)` and `SqliteStore.idempotent(actorContext, input, callback)` require a server-derived authenticated actor; request payloads cannot supply it. SQLite is opened only by `packages/storage-sqlite/src/database.ts`; migrations 0001..0011 are checksummed and fail closed on drift. `SqliteStore.doctor()` compares stored names/checksums with the packaged canonical SQL. Identity, binding, event, and memory repositories append audit events automatically using that actor inside the same transaction. Audit failure rolls back both the domain mutation and every earlier audit event in the transaction. Idempotency records use request digest, append `idempotency.complete` once, and replay without a second mutation or audit event.

Packaging contract: each package tarball must expose coherent `exports`, `types`, `files`, `dist/index.js`, `dist/index.d.ts`; storage includes exactly the eleven SQL migrations. Reproducibility is measured by sorted archive paths and per-path byte SHA, not tar metadata. Current package digests and command evidence are recorded in `artifacts/s2-evidence.json` after the gate.

Runtime limit: Node `node:sqlite` is experimental on the supported Node >=22.16 runtime. The gate records this limitation explicitly; it does not hide experimental warnings or claim API stability beyond the frozen package surface.

Gate: lint, typecheck, targeted/full tests, build, owner scan, migration/doctor/backup fresh process, package reproducibility, external install, dependency audit, then S0 and S1 regression in a complete isolated copy. Evidence is written PENDING before execution and only becomes PASS when every named step passes and targeted assertions are >0. No S3 approval is implied.
